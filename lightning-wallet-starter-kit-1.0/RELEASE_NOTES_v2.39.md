# Lightning Wallet v2.39.0

## Production scope

- Adds explicit mainnet read-only wallet connection for Ethereum, Solana, and TRON.
- Keeps all mainnet transaction execution gates disabled until provider configuration and authorized-wallet acceptance are complete.
- Preserves non-custodial signing: private keys, mnemonics, and Keystore material never leave the browser or wallet extension.

## Wallet connection hardening

- Verifies Ethereum Mainnet chain ID `1`, the full Solana Mainnet genesis hash, and TRON Mainnet chain ID / exact official RPC hostname.
- Keeps the connected public-wallet session across client routes.
- Invalidates the entire session on account, network, or provider disconnection events.
- Revalidates the active network and account before balance reads or optional ownership signatures.
- Requires a separate user click before reading a public balance; no balance is fetched automatically after connection.
- Mainnet self-test broadcast is blocked in code and hidden in the mainnet UI.
- Testnet self-test remains isolated to Sepolia, Solana Devnet, and TRON Nile / Shasta.

## Release boundaries

- No production transaction, token transfer, swap, LP action, bridge action, or launch transaction is generated by the mainnet connection acceptance flow.
- WalletConnect still requires a production Project ID.
- GasFree, holder data, Flash Loan application integration, automation delivery, and authorized-wallet transaction acceptance remain fail-closed readiness gates.
